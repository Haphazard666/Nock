**Summary:** 10 of 11 criteria pass. **Criterion 7 fails with Nock's default settings** (6.5 % of one core while playing). The radio itself costs 1.3 %. The rest comes from Nock's existing equaliser/glow on the pill, which runs for any playing media. This needs a PM decision (see "Criterion 7" below). I did not change that existing feature.

### Behaviour

- **Network only on user action.** Opening the Radio tab loads the Top list for the Windows region (`GetUserDefaultGeoName`, here `IL`) once per session, and again only if it failed. Search runs on Enter. Play calls `/json/url/<uuid>` once. Nothing at start-up: with no tab opened, the trace file is never created.
- **The Top list is cached for the session.** Re-opening the tab shows it at once. This avoids a PowerShell run every time the mouse wheel passes over the tab row.
- **One search box** ("Name, genre, or country code like DE"). A two-letter code is a `countrycode=` search. Anything else runs the name search and the tag search in the **same** PowerShell process (two HTTP requests to the same mirror). Results alternate name/tag, no repeats, at most 50. This is how "jazz" (tag) and "BBC" (name) both work from one box.
- **Two fetches in flight.** T2 kept one result and a newer one replaced it. A Top fetch and a search finishing close together would have lost the Top list (left spinning). Results are now kept per id (newest 4).
- **Playback.** A player is created on play and dropped on stop or failure (`Pause` + `Close`). Status: `Connecting...` until `MediaOpened`/`Playing`, then `Playing`. `Buffering` after open shows `Buffering...`, never an error. `Paused` (from the Windows flyout or Nock's Media card) shows `Paused`, and the strip button resumes. `MediaFailed` maps to "Station offline", "Format not supported" or "Network error". The 10 s one-shot timer shows "Station not responding". Events from an old player are dropped by generation number.
- **Colour-blind safe** (Yuval is red/green colour blind). Every state has a shape and words:
  - errors: an amber triangle with "!" plus amber text
  - playing: three blue level bars plus "Playing · IL · MP3 · 128 kbps"
  - connecting/buffering: three dots
  - paused: two bars
  - stopped: a square
  - favourites: a filled star; the rest: an outline star
  - selected list: a brighter filled chip
  - the playing row: level bars as well as a tint

  Amber and blue are both much brighter than the grey around them.
- **Favorites.** `name|url|uuid|countrycode|codec|bitrate|hls`. The star saves at once. They load on the first open of the tab, not at start-up.

### Criterion 7: what needs a decision

While anything plays, Nock's collapsed pill runs its existing equaliser and music glow: `eq_active()` → a 50 ms animation timer, `sys::audio_peak()` and a re-render, about 20 times a second. Nock's own radio shows up as a media session (GSMTC, as T1 found), so the pill animates for it, exactly as it does for Spotify. That costs about 5 % of one core here. The radio playback itself is 1.3 %, close to T1's 1.1 to 1.3 %.

Options for the PM:
- (a) Measure criterion 7 with `eq_animation=0`, or as "extra over Nock with the same music playing elsewhere". Radio passes either way.
- (b) Have the pill skip the animation for Nock's own radio session. This changes an existing feature, so I did not do it.
- (c) Make the equaliser cheaper for everyone (outside this task).

## How it was tested

- Dev build started from a scratch folder holding a canary file `x`, with `NOCK_RADIO_TRACE` pointing at a scratch file (ms timestamps for fetch start/done, list shown, player events, close time).
- Clicks and typing were posted to the `NockWindow` (`WM_LBUTTONDOWN`/`UP`, `WM_CHAR`, `WM_MOUSEWHEEL`) at logical coordinates. Screenshots checked each step.
- CPU, private bytes and threads were sampled from outside the process. "Our" threads are those whose Win32 start address lies inside nock.exe.
- Three test favorites (unknown host, 404, a host that never answers) were written to `%APPDATA%\Nock\stations.txt` for criteria 4 and 11. The file did not exist before and was deleted afterwards. `config.ini` was restored from a backup, and the installed Nock was restarted.

## Known issues

1. **Criterion 7 with defaults:** see above.
2. **Stop blocks the UI thread for about 0.29 s** (`Pause` + `Close`, 281 to 289 ms every time; T1 saw the same). Audio stops at `Pause`. The panel just doesn't redraw for that moment. Moving `Close` off the UI thread would need a thread, so I left it.
3. **A stream that drops after it opened** stays on "Buffering..." (no timeout after `MediaOpened`). Not covered by the spec.
4. **Two-letter names** (for example a station called "RT") are read as a country code, as the hint says.
5. **App start rewrites `config.ini` once to add `radio=1`.** This is Nock's normal way of adding a new key. It ran on this machine during the preview test and live runs. Values are kept.
6. **The Top list is cached for the session.** It can be up to one Nock run old. No refresh button (none in the spec).
