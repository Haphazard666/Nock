### Criterion 12: needs a PM decision

**Real drop (Yuval turned Wi-Fi off; the PC has no other uplink).** Glglz (MP3 128k) was playing.

| Time (from Wi-Fi off) | What happened |
|---|---|
| 0 s | Wi-Fi off (adapter state seen by a watcher) |
| some time later | **Audio went silent** (Yuval). Player events: none. Strip: "Playing" |
| 110 s | Wi-Fi back on |
| 154 s | First player event since the cut: `Buffering`, then `Playing` 340 ms later. Audio came back by itself (Yuval) |

The player never told Nock that it ran dry while the network was gone. The spec's rule, "One-shot timer started on entering Buffering after MediaOpened", cannot fire, because there is no Buffering. I did not build around this. Options for the PM (each needs a spec change):

- (a) **Arm the stall check from a network event.** WinRT `NetworkInformation.NetworkStatusChanged` while playing starts the same one-shot 15 s timer. When it fires, compare `PlaybackSession.Position` with its value when it was armed: if it has not moved, show "Connection lost". One event, one timer, one read: no polling. It misses a drop that is not on this PC (the station or the ISP), which is the relay case below. Buffering still covers that one.
- (b) **A position watchdog:** a one-shot 15 s timer re-armed while `Position` advances (for example from `PositionChanged`). This catches every kind of drop, but `PositionChanged` fires several times a second while playing. That is a steady trickle of window messages, close to polling, so it would need a CPU check against criterion 7.
- (c) **Accept it:** keep the timer on Buffering only, and reword criterion 12 to "when the player reports Buffering". The audio then comes back by itself after a short drop, as seen here.

I would pick (a). The local relay test below shows the Buffering path itself works.

### Criterion 12: local simulation

A local relay (`127.0.0.1:8765`, test only, not committed) played the real Glglz stream for 12 s, then either held the connection open sending nothing (a dead link) or hung up.

- **Dead link:** the player kept playing what it had already buffered, then reported Buffering. "Connection lost" came **15.0 s after Buffering** (stall timer). Between the relay going quiet and Buffering: 48.4 s.
- **Hang-up:** the player played its buffer, then reported `MediaEnded`, and the strip showed "Connection lost" **at once** (7 ms). Before this task that ended as "Paused", which was wrong.
- **Why so long a buffer:** the station sends a burst when you connect. In 12 s the relay passed on 1,130,496 bytes = **70.7 s** of 128 kbps audio. So after a real drop the listener keeps hearing the station for up to about a minute. "Connection lost" comes 15 s (dead link) or 0 s (hang-up) after the audio actually stops. Timed from the moment the audio stops, that is within 15 s. Timed from the cut, it depends on the station's burst.

## How it was tested

- The installed Nock was quit, `config.ini` was backed up, and the dev build ran from a scratch folder holding a canary file `x`, with `NOCK_RADIO_TRACE` set (ms timestamps for fetches, player events, strip status, mute and close times).
- Input was posted to the dev build's own `NockWindow` (`WM_LBUTTONDOWN`/`UP`, `WM_CHAR`, `WM_KEYDOWN`, `WM_MOUSEWHEEL`). Captures came from `PrintWindow` of that window only, so no other window is in them.
- Measurement settings (`stats=0`, `buddy=0`, `scenes=0`, `eq_animation=0`, `auto_close=0` so the panel stayed open under posted clicks) were set for the run. `config.ini` was restored from the backup afterwards and compared line by line (identical). The installed Nock was restarted.
- From the error tests on, the dev build ran with `APPDATA` pointed at a scratch profile (a copy of `config.ini` plus test favorites), so Yuval's own `%APPDATA%\Nock` never got a `stations.txt`. `fs_hide=0` in that profile kept the panel up while the screen was locked.
- A/B for criterion 6: the T3 build (main) through the same sequence gave 1.00 % before, 1.11 % then 0.57 % after stop. The after-stop numbers wobble with Media Foundation winding down; the new build is no worse.
