### How it works

- **Station** fields: `uuid`, `name`, `countrycode`, `codec`, `bitrate` (u32, 0 = unknown), `hls` (bool), `tags`, `url` (`url_resolved`). Display helpers: `codec_label()` gives `HLS` when `hls`, and `bitrate_label()` only returns a value when bitrate > 0.
- **Line format** from PowerShell: `uuid|name|countrycode|codec|bitrate|hls|tags|url_resolved`, prefixed `ST|`. PowerShell strips `|`, CR, LF and tabs from every field. A line is skipped if:
  - it doesn't have exactly 8 fields
  - it has no uuid or no name
  - the URL isn't http(s)

  Bad bitrates become 0.
- **Script output** also carries:
  - `SRV|host`: the mirrors in the order they'll be tried
  - `OK|host`: the mirror that answered
  - `FAIL|host|why`
  - `ERR|why`

  Unknown lines are ignored.
- **Mirrors.** The first fetch in a Nock session has no mirror list, so the script downloads `https://all.api.radio-browser.info/json/servers` itself and shuffles it. Rust keeps the list in memory (session only, nothing on disk) and drops mirrors that fail. Later fetches pass the cached list, shuffled in Rust (xorshift seeded from the clock), so there is one PowerShell launch per fetch. Each fetch tries up to 4 mirrors with a 6 s timeout each.
- **Queries** (`Query::Top(Option<cc>)`, `Name`, `Tag`, `Country`) map to the spec's endpoint with `order=clickcount&reverse=true&hidebroken=true&limit=50`. `Top` with no valid two-letter code means no country filter. Requests send `User-Agent: Nock/<version>`.
- **Fetch thread.** `tuner::fetch(hwnd, query) -> id` spawns one thread. It runs the script through the existing `sys::powershell` (base64 `-EncodedCommand`, no window), stores the result, posts `WM_TUNER` (`WM_APP + 13`) with WPARAM = id, and exits. The UI calls `tuner::take(id)`. A newer fetch replaces an older result the UI has not taken. Errors come back as short text ("Network error", or the script's `ERR` reason).
- **Click call.** `tuner::click(uuid)` sends `/json/url/<uuid>` on its own short thread, fire and forget, with no message.
- **Default country.** `tuner::default_country()` uses `GetUserDefaultGeoName`. It returns a two-letter code or `None` (for example `001`, the world), which means no filter. This machine gives `IL`.
- **UTF-8.** The script sets `[Console]::OutputEncoding` to UTF-8 and decodes the HTTP body as UTF-8 itself. Windows PowerShell 5.1 otherwise mangles non-ASCII names.
- **Security** (spec criterion 8):
  - Search text is percent-encoded in Rust. Only RFC 3986 unreserved characters (letters, digits, `-_.~`) stay as they are; everything else becomes `%XX`.
  - The script builder refuses any path with a character outside `[A-Za-z0-9-_.~%&=?/]`.
  - Mirror names from the network must match `[a-z0-9.-]`, and uuids `[0-9a-fA-F-]`. Anything else is left out or refused.
  - The script is passed base64-encoded, so command-line quoting plays no part.
- **Favorites** (`store.rs`): `%APPDATA%\Nock\stations.txt`, one per line `name|url_resolved|uuid|countrycode|codec|bitrate`, with two `#` comment lines at the top.
  - Loading skips blank lines, comments, lines with no name, lines with a non-http(s) URL, and repeated URLs. Missing trailing fields are empty, a bad bitrate is 0, and extra fields are ignored.
  - Saving replaces `|`, CR and LF in fields with spaces.
  - A missing file means no favorites, and no file is created until something is saved.
  - `tuner::load_favorites()` / `save_favorites()` convert to and from `Station`.
  - The favorites code compiles on Windows and in tests only (`cfg(any(windows, test))`). The Linux port has no Radio tab, and this way the Linux build gets no dead-code warnings while Linux `cargo test` still runs the store tests.

## Findings for the PM

1. **Criterion 1 (Top list in about 3 s) is borderline when cold.** The first fetch in a Nock session took 1.6 to 3.8 s (two of five runs over 3 s). That includes a PowerShell start (~0.5 s), the server-list request and the query. Later fetches in the same session take 1.1 to 1.6 s. Measured from a test process, not inside Nock.
2. **The Radio Browser server list currently contains only one mirror** (`de1.api.radio-browser.info`). "Try the next server on failure" is built and unit-tested, but can't be exercised live today. If `de1` is down, every fetch fails with `ERR|no server answered` (or the server-list error).
3. **The favorites line format has no `hls` field.** A starred HLS station comes back from `stations.txt` with `hls = false`, so its codec column shows what Radio Browser said (often `AAC`) instead of `HLS`. Playback isn't affected. Fix if wanted: add `hls` as an optional 7th field (old files still load). I did not do it because the spec fixes the format.
4. **Country search is `countrycode=` only**, as the spec says. Typing "Germany" returns nothing; "DE" works. Radio Browser also has `country=<name>`. The UI may want to hint "two-letter code", or the spec could allow the name search.
5. Tag search is an exact tag match on Radio Browser's side ("jazz" works). The "jazz" top result was "Christmas FM Non-stop!", which is tagged jazz and has a high click count.
